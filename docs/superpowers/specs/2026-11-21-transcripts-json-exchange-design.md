# Дизайн: обмен расшифровками в JSON (выгрузка и импорт)

Дата: 2026-11-21
Статус: утверждено пользователем (обе функции в Настройках)

## Зачем

Пользователь хочет забрать из приложения всю накопленную информацию — только
расшифровки — в JSON-файл, отправить её в мессенджеры через стандартный лист
«Поделиться» и затем импортировать такой файл обратно (например, на другом
устройстве), с защитой от дублей через уникальный идентификатор записи.

## Выгрузка

В «Настройках» (новая секция «Данные») кнопка **«Выгрузить расшифровки (JSON)»**.
По нажатию собирается JSON со всеми активными (не удалёнными) записями и
открывается системный лист поделиться с временным файлом
`weeklywins-transcripts.json` — пользователь сам выбирает мессенджер или
«Сохранить в Файлы».

### Формат JSON

```json
{
  "app": "weeklywins",
  "exportedAt": "2026-11-21T12:00:00+05:00",
  "recordings": [
    {
      "id": "3f6f8a24-9d21-4c4a-9b3e-2d6a0c1e5f77",
      "recordedAt": "2026-11-15T09:41:00+05:00",
      "duration": 720,
      "transcript": "Обсудил с Анной план релиза…"
    },
    {
      "id": "8a1b…",
      "recordedAt": "2026-11-20T18:20:00+05:00",
      "duration": 480,
      "transcript": null
    }
  ]
}
```

- `id` — существующий `Recording.id` (UUID). Это ключ дедупликации при импорте.
- Записи без расшифровки включаются с `transcript: null` — выгрузка полная.
- Удалённые записи не включаются (у них нет расшифровки).
- События (дела) **не включаются** — только расшифровки.
- Сортировка по `recordedAt`, старые первыми. Даты — ISO 8601 с таймзоной,
  длительность — секунды (число). UTF-8, форматирование с отступами.
- Обратная совместимость: файлы, выгруженные до появления `id`, декодируются
  (`id` отсутствует → запись при импорте считается новой).

## Импорт

Рядом в секции «Данные» кнопка **«Импортировать расшифровки (JSON)»** —
системный выбор файла (`.json`). После разбора показывается alert с итогом:
«Импортировано записей: N. Пропущено дублей: M.»

Правила импорта:

- **Дедупликация по `id`**: запись пропускается, если запись с таким UUID уже
  есть среди активных (не удалённых). Удалённые записи такой проверкой не
  считаются — импорт старого файла может их «вернуть» (осознанное решение:
  выгрузка — это бэкап).
- Записи без `id` (старый формат) импортируются как новые со свежим UUID —
  без защиты от дублей.
- Импортированная запись: `state = .saved`, аудио нет. Если `transcript != nil`
  → `processingState = .completed`, `transcriptUpdatedAt = .now`, события
  заново извлекаются `EventExtractor.extract` (детерминированный экстрактор,
  как при старте хранилища), `eventsManuallyEdited = false`. Если
  `transcript == nil` → `processingState = .failed`, сообщение
  «Аудио недоступно» — чтобы запись не уходила в автоматическую расшифровку
  без аудио.
- Повреждённый/чужой JSON → alert «Не удалось прочитать файл», состояние
  приложения не меняется.
- Ничего не отправляется на сервер: файл выбирает и открывает только
  пользователь.

## Не-цели

- Нет выгрузки/импорта аудио, событий отдельно от расшифровок, настроек.
- Нет автоматических/фоновых обменов.
- Формат не версионируется (одна версия, обратная совместимость — опциональный `id`).
