# Удержание экрана во время тестов на iPhone

Сборка Debug содержит режим тестовой сессии. Он устанавливает `UIApplication.isIdleTimerDisabled`, пока WeeklyWins находится на переднем плане, и восстанавливает предыдущее значение после завершения. Между отдельными запусками тестов обёртка открывает WeeklyWins снова. Системная автоблокировка сохраняет пользовательское значение.

На проверенном iPhone меню автоблокировки предлагает значения от 30 секунд до 5 минут. Выбраны 5 минут. Режим приложения позволяет удерживать экран на время тестов через публичный API UIKit. Во время длительного пребывания в Settings, Shortcuts или Home применяется поведение активного приложения и iOS.

## Начало серии

Подключить iPhone по USB и установить актуальную сборку Debug с поддержкой тестовой сессии. Первая разблокировка выполняется владельцем телефона. Скрипт проверяет отсутствие активной аудиозаписи перед первоначальным перезапуском приложения, записывает состояние восстановления и ожидает подтверждение от запущенного процесса.

```sh
python3 scripts/device-test-session.py begin \
  --device 00008140-001C308C0AD8801C
```

В подтверждении должны присутствовать `active=true`, `idleTimerDisabled=true` и PID приложения.

## Команда внутри серии

```sh
TEST_RUNNER_RUN_DEVICE_ASR_ACCEPTANCE=1 \
python3 scripts/device-test-session.py run \
  --device 00008140-001C308C0AD8801C \
  --command xcodebuild -project WeeklyWins.xcodeproj -scheme WeeklyWins \
    -destination 'platform=iOS,id=00008140-001C308C0AD8801C' \
    -derivedDataPath /private/tmp/weeklywins-device-session21-derived \
    -only-testing:WeeklyWinsTests/ASRAcceptanceTests/testNativeRussianOneMinute \
    test-without-building
```

`run` автоматически создаёт и закрывает собственную сессию. При существующей внешней сессии команда возвращает приложение в режим удержания экрана. Вложенные CLI-вызовы наследуют владельца, независимые процессы используют блокировку файла состояния.

## Завершение и восстановление

```sh
python3 scripts/device-test-session.py end \
  --device 00008140-001C308C0AD8801C
```

Подтверждение должно содержать `active=false`. Состояние `idleTimerDisabled` возвращается к значению, захваченному приложением перед сессией. При ошибке восстановления сохраняется локальный файл состояния для повторной команды `end`.

По умолчанию файл состояния находится в `/private/tmp/weeklywins-device-test-session.json`, журналы — в соседнем каталоге `.logs`. Параметр `--state` задаёт отдельный файл для другого устройства. Устройство хранит управляющий marker и подтверждение с PID в Application Support. Временная ошибка чтения marker сохраняет активную сессию. Явное `enabled=false` завершает удержание. Сборка Release использует обычное поведение приложения.

## Проверка сборки 21

На iPhone 16 Pro с iOS 27.2.1 сессия включена в 04:01 UTC 18 ноября 2026 года. Приложение подтвердило `active=true`, `idleTimerDisabled=true`, PID 6725. После 6 минут 35 секунд ожидания CoreDevice сообщил `passcodeRequired=false`. Затем физический минутный ASR-тест запустился без дополнительного запроса разблокировки. Обёртка вернула WeeklyWins на передний план уже с PID 6749 и получила новое подтверждение удержания экрана.

После `end` приложение подтвердило `active=false`, `idleTimerDisabled=false`. Локальный checkpoint удалён. Исходное системное значение автоблокировки — 5 минут. Журнал обёрнутого запуска находится в `/private/tmp/weeklywins-awake-wrapped-native.log`.

Полная регрессия симулятора прошла с 105 успешными проверками, 8 пропусками и 0 ошибками, всего 113. Журнал находится в `/private/tmp/weeklywins-device-session21-full.log`. Сборка Release прошла отдельно. Три Swift-теста проверяют исходное состояние таймера, отмену и промежуточно неполный marker. Восемь Python-тестов проверяют жизненный цикл, ошибку команды, прерывание, активную запись, восстановление и настоящий вложенный CLI-вызов.
